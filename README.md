# pj design system

Design tokens and generators behind [pj-25.github.io](https://pj-25.github.io) and my terminal, built intent-first. Every value traces back to a written reason, and every colour pair is contrast-checked before it ships.

One source, several surfaces:

| Surface | Output | Generated by |
|---|---|---|
| Web (reading surfaces) | `dist/tokens.css`: CSS custom properties, light and dark | `lib/build-tokens.mjs` |
| Terminal (working surfaces) | `dist/terminal/ghostty/pj-{light,dark}`, `dist/terminal/nvim/colors/pj.lua` | `lib/build-terminal.mjs` |

## Principles the tokens encode
- **Intent before aesthetics.** Tokens name roles (`color.text.muted`), never values (`grey-600`).
- **Show the evidence.** Status and evidence colours are a vocabulary of their own (`verified`, `described`, `in-progress`) and are always paired with shape and text, never colour alone.
- **Meaning over decoration.** Neutrals (paper and ink) do most of the work, with one accent (deep teal). No gradients, glass or neon.
- **Craft is the floor.** Every text/surface pair meets WCAG 2.x AA in both themes, or the build fails.
- **Notebook and workbench.** Reading surfaces get serif headings and comfortable density; working surfaces (terminal, tools) stay sans and dense, built from the same materials.

## Tokens
Source files are [W3C Design Tokens Format Module 2025.10](https://www.designtokens.org/tr/2025.10/format/) JSON in `tokens/`:
- `base.tokens.json`: reference palette (`ref.*`, never emitted), semantic light colours, type, space, radius, size and motion.
- `dark.tokens.json`: semantic colour overrides only. Dark is tuned separately, not inverted.
- `terminal.tokens.json`: ANSI 0–15 and terminal UI colours for both themes, aliasing the same reference palette.

Contrast requirements live on the tokens themselves:
```json
"muted": { "$type": "color", "$value": "{ref.color.ink.600}",
  "$extensions": { "io.github.pj-25": { "contrast": { "on": ["color.surface.page", "color.surface.raised"], "min": 4.5 } } } }
```
Generated CSS uses the `--pj-` prefix: `--pj-color-text-muted`, `--pj-font-size-h2`, `--pj-space-4`. Dark applies under `prefers-color-scheme: dark` unless `[data-theme="light"]`, and under `[data-theme="dark"]`. `[data-surface="working"]` swaps the serif display face for the text face.

## Use
```sh
npm install https://github.com/pj-25/design-system/archive/refs/tags/v0.1.0.tar.gz
```
```js
import 'pj-design-system/tokens.css';                       // in your layout
import { lintRawColours, lintFontSizes } from 'pj-design-system/lib';
lintRawColours('src');   // → ['src/x.css: #fff', …]   no raw colours outside tokens
lintFontSizes('src');    // → […]                     no literal font sizes
```
Terminal: copy `dist/terminal/ghostty/*` to `~/.config/ghostty/themes/` and set `theme = light:pj-light,dark:pj-dark`. Copy `dist/terminal/nvim/colors/pj.lua` into your Neovim config's `colors/` and run `:colorscheme pj` (it follows `'background'`). The display face (Source Serif 4, OFL) is self-hosted by each consumer; the tokens name it and a metric-matched Georgia fallback.

## Develop
```sh
npm test         # unit tests (contrast maths, aliases, cycles, lints, generators)
npm run build    # regenerate dist/
npm run check    # fail if dist/ is stale or any contrast gate fails
```
Node ≥ 22, no dependencies. Generated files are never edited by hand.

## Versioning
Semver. Renaming or removing a semantic token is a breaking change, and deprecated tokens stay aliased for one minor version.
